# The AI-09 framework trial: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the 0064 chat flow in both LangGraph and Microsoft Agent Framework on the same shared parts, run the chat's AI-03 cases through both under a $10 limit, and bring a four-part scorecard back to Vestagraph for the founder's choice of framework (AI-04).

**Architecture:** Two Vestagraph pull requests and one local trial. **PR 1** (this branch, `docs/ai-09-trial-design`): the design, this plan, about 10 new comparison cases in the AI-03 set (version 3) and the records. **The trial** (local only, `~/source/code/portfolio/vestagraph-ai09-trial`, never pushed): two projects generated from `house-template-fastapi` v0.11.1 (`llm: langchain` and `llm: maf`) and a shared package `trial_shared` both depend on. **PR 2**: the results review with a recommendation, then (after the founder's choice) decision 0066 and the package approval.

**Tech Stack:** Python 3.14 and uv; the template's gateways (LangChain/LangGraph, MAF) at v0.11.1; each framework's AG-UI adapter; the `anthropic` SDK (BE-43); LangSmith EU (a trial project); PostgreSQL in Docker for the template; pytest.

**Spec:** `docs/superpowers/specs/2026-11-21-ai-09-trial-design.md` (approved by the founder, 21 Nov 2026).

## Global Constraints
- Models (0064): `claude-haiku-5-5` for the classifier, single agent, orchestrator and workers; `claude-sonnet-5-5` for the writer, the checker's second step and AI-15's judge. At most 3 areas per comparison.
- A **run** is one case, including all its repetitions (a rule case's 3 runs of AI-15 are one run here). Spend: **$10 in total for the whole trial across both frameworks, $1 per run (per case)**, in the founder's test Anthropic workspace. The shared cost counter is authoritative and stops a run before a call that could pass either limit; the template's budget stays on as a second guard.
- Same prompts, tools, models, settings and cases in both frameworks. Any framework-specific workaround is recorded in the results review (it counts under maintenance).
- Tools read `packages/fixtures/generated/area-result.json` and `council-result.json`, and the input values in `packages/fixtures/data/postcode-area.json` and `council-area.json` (each with its source), from a Vestagraph checkout at a recorded commit; they calculate nothing (rule 2).
- Clean-up: after the founder's choice, and also if the trial is abandoned, remove the Docker container and its volume and delete the trial folder.
- Test conversations only, synthetic postcodes (NB1 4XY, NB7 1RR, NB9 9ZZ, ZZ4 4ZZ, ZZ5 5ZZ). The API key is read from the founder's providers file in a subshell, never printed, logged or committed.
- Framework and library APIs are checked against their official documentation for the installed version before use (AGENTS.md); cite the page in the trial's notes.
- No framework package enters Vestagraph in this plan. Vestagraph commits: `docs:` or `test:`, no agent attribution; `make check` before every push.

## Review Focus
1. **A comparison whose workers return different `kind`s or a failed tool on one side:** the writer keeps each side's own gap ("Not known right now", Unavailable), never zero; Task 1's new cases and Task 4's checker tests pin it.
2. **A run that hits the $1 limit mid-comparison:** the counter refuses the next call, the run is marked "stopped at limit" and excluded from quality scores, not counted as a fail; Task 4's counter test pins it.
3. **Streaming differences masking speed:** time to first text is measured at the AG-UI test client for both, from the same send to the first text event; Task 7's runner records both clocks identically.
4. **An AI-03 case that depends on stubs the trial's tools don't read** (for example `store-record`): the runner applies the stub in the shared tool layer, the same for both; Task 4 pins one stub case.
5. **A framework that retries a failed model call silently:** retries cost money and time; the counter counts every call, and the results review reports retries per framework; Task 7 records them.

**Interfaces:**
- Produces:
  - `ToolResult(kind: str, data: dict[str, Any])`; `TOOLS: dict[str, Callable[[dict[str, Any]], ToolResult]]`, one entry per tool name the chosen cases call, derived by script (see Step 0), reading the generated files and the input data files (`postcode-area.json`, `council-area.json`); they calculate nothing.
