# Pilot API (#93) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the placeholder with the pilot's FastAPI API (`vestagraph-api-live`): `/healthz` as today, and `POST /api/area-check` answering from the fixture data through the tested area functions, closed to the public until the Privacy notice is live.

**Architecture:** The per-postcode assembly moves from the generator into `vestagraph_area.area_check`, which both the generator and the new `vestagraph_api` package call. `vestagraph_api` is the web layer of the founder's FastAPI template (v0.11.1, rendered with database, AI and storage off), renamed into the workspace. The release builds a new image from `deploy/api.Dockerfile`; the server cut-over happens after merge, in the private infrastructure repository.

**Tech Stack:** Python 3.14, uv workspace, FastAPI 0.162.x (`fastapi[standard-no-fastapi-cloud-cli]`), pydantic-settings, structlog, uvicorn; tests with pytest, httpx, asgi-lifespan; import-linter; Docker; GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-26-pilot-api-design.md`

## Global Constraints

- One `uv.lock`; add packages with `uv add` (it asks the founder's approval; the founder approved this exact set on 26 Nov 2026: "Approve, standard bundle"). Runtime: `fastapi[standard-no-fastapi-cloud-cli]>=0.162.0,<0.163`, `pydantic-settings>=2.16.1`, `structlog>=26.1.0`. Test group: `httpx`, `asgi-lifespan>=2.1.0`, `import-linter>=2.15`. Nothing else.
- Python 3.14 for project code; mypy strict and ruff as configured; test names `test_<method>_<condition>_<result>`.
- `make check` stays Docker-free.
- No figure is calculated or typed in `vestagraph_api` (rule 2): it calls `vestagraph_area` and quotes records from `postcode-area.json`.
- No postcode, request body, query string or client address in any log line (0014).
- `AREA_CHECK_OPEN` defaults to off; when off, `POST /api/area-check` returns a problem-details 503 titled "Not available yet" and does not read the body.
- Template files are the founder's own (AGENTS.md exception, 0040, 0049): copy only from the recorded release v0.11.1; record its tag and commit in the pull request.
- `packages/fixtures/generated/area-result.json` must stay byte-identical (proved by `make generated-check`).
- No agent attribution in commits or the pull request.

## Review Focus

- A postcode typed in another case or with extra spaces (`nb1  4xy`): found, the same as `NB1 4XY`. Test in Task 2 (`test_check_postcode_case_and_spaces_found`).
- A body that is not JSON, or JSON with `postcode` as a number or missing: 422, and the response text never contains the input. Test in Task 4 (`test_area_check_bad_body_returns_422_without_input`).
- A huge body (over 16 KiB) while open: 413 before parsing. Test in Task 4 (`test_area_check_body_over_limit_returns_413`).
- The closed endpoint with a postcode in the body: 503, and no log line or response text contains the postcode. Test in Task 4 (`test_area_check_closed_returns_503_and_logs_no_postcode`).
- Production settings: `/docs` and `/redoc` return 404, `/openapi.json` is served. Test in Task 3 (`test_create_app_production_hides_docs`).

### Task 2: The per-postcode area check in `vestagraph_area`

**Files:**
- Create: `packages/vestagraph-area/src/vestagraph_area/area_check.py`

- Test: `packages/vestagraph-area/tests/test_area_check.py` (new)

**Interfaces:**
- Consumes: `PostcodeArea.nations` (Task 1).
- Produces, in `vestagraph_area.area_check`:
  - `json_number(value: Fraction | int) -> int | str` (moved unchanged from the generator).
  - `postcode_result(registry: Registry, area: PostcodeArea, priorities: Sequence[Priority], postcode: str) -> dict[str, Any]`: exactly one entry of `area-result.json`'s `postcodes` (the dict the generator builds today, with `_distances` and `_buses` moved here).
  - `postcode_key(text: str) -> str`: whitespace removed, then `casefold()` (as `council_for_postcode` does).
  - `PostcodeLookup` (frozen dataclass): `state: Literal["found", "notFound", "notCovered"]`, `postcode: str | None` (the data's spelling when found or not covered), `nation: str | None`.
  - `check_postcode(area: PostcodeArea, typed: str) -> PostcodeLookup`: matches `postcode_key(typed)` against the data's postcodes; England → `found`; another nation → `notCovered`; no match (including `unknownPostcodes`) → `notFound`.

- [ ] **Step 2: Run** `uv run --locked pytest packages/vestagraph-area/tests/test_area_check.py -q`. Expected: FAIL (`ModuleNotFoundError`).
- [ ] **Step 3: Implement** the module; the generator's loop body becomes `postcodes.append(postcode_result(registry, area, priorities, postcode))`, and `area_generator` imports `json_number` from `vestagraph_area.area_check` so `from vestagraph_generator.area_generator import json_number` still works.
- [ ] **Step 4: Run** the tests, then `make check`. Expected: PASS, "Generated files: up to date."
